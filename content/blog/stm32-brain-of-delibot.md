Delibot은 두 가지 모드로 움직입니다. 사람이 무선 조종기로 직접 몰거나, 라즈베리파이가 자율주행 명령을 내리거나. 문제는 이 둘이 언제든 동시에 신호를 보낼 수 있다는 점입니다. 그래서 로봇의 진짜 두뇌인 STM32F401CCU6 컨트롤러는 "누구 말을 들을지"부터 매 순간 판단해야 합니다.

## 하드웨어부터 짚고 가기

Delibot은 2륜 차동 구동 로봇입니다. STM32F401CCU6(ARM Cortex-M4F)가 L298N 모터 드라이버를 PWM으로 구동하고, 좌우 바퀴에 달린 쿼드러처 엔코더와 BNO080 9축 IMU로 실제 주행 상태를 읽어옵니다.

## 5ms마다 반복되는 제어 루프

컨트롤러는 200Hz, 즉 5ms마다 다음 네 단계를 반복합니다.

1. IMU 리포트를 논블로킹으로 폴링
2. 명령 소스 판단 — CRSF 링크가 300ms 이내로 살아있으면 CRSF, 아니면 라즈베리파이의 마지막 속도 명령(500ms 데드맨 타임아웃), 둘 다 없으면 0
3. 목표 선속도·각속도를 좌우 바퀴 속도로 변환하고, 엔코더 피드백 PID로 PWM 듀티를 계산
4. 20ms마다 라즈베리파이에, 100ms마다 CRSF로 텔레메트리 전송

핵심은 2번입니다. **CRSF 신호가 살아있으면 무조건 CRSF가 이깁니다.** 사람이 조종기를 들고 있다면 언제든 로봇을 직접 통제할 수 있어야 하기 때문입니다. RC 링크가 끊긴 경우에만 라즈베리파이의 자율 명령으로 넘어가고, 그마저 500ms 넘게 끊기면 모터를 그대로 정지시킵니다.

## 바퀴 속도는 PID로 잡는다

엔코더로 측정한 실제 바퀴 속도가 목표 속도를 따라가도록 표준 PID 제어를 사용합니다.

$$
u(t) = K_p e(t) + K_i \int e(t)\,dt + K_d \frac{de}{dt}
$$

IMU를 함께 쓰는 모드에서는 여기에 요(yaw) 방향 오차에 대한 PID를 하나 더 얹어, 엔코더만으로는 잡기 힘든 미세한 직진 오차까지 보정합니다.

## STM32 ↔ 라즈베리파이는 직접 만든 UART 프로토콜로

USART2(115200bps, 8N1)로 연결된 두 보드는 아래 형식의 프레임을 주고받습니다.

```
[0xFF][LEN][CMD][DATA...][CRC]
```

CRC는 CMD와 DATA 바이트를 전부 XOR한 1바이트 체크섬입니다.

```c
uint8_t crc = cmd;
for (int i = 0; i < len; i++) {
  crc ^= data[i];
}
```

체크섬이 맞지 않으면 프레임을 버리고 다음 `0xFF`를 찾아 다시 동기화합니다. `VELOCITY` 명령은 목표 속도 전달과 동시에 하트비트 역할도 겸해서, 500ms 안에 들어오지 않으면 라즈베리파이 링크가 끊긴 것으로 간주합니다.

다음 글에서는 실제 로봇에서 이 PID 게인과 엔코더 CPR, 트랙 폭 같은 물리 상수들을 어떻게 캘리브레이션했는지 정리해보겠습니다.
